# Hermes Agent Skill — BPMN Diagramming

## 1. Что это за навык

`bpmn-diagramming` — специализированный навык для Hermes Agent, предназначенный для создания BPMN 2.0 диаграмм **для любых бизнес-процессов**: продажи, закупки, производство, маркетинг, IT-разработка, HR, документооборот, логистика, сервис, финансы, качество, проектное управление и т.д.

Навык решает задачу как инженер бизнес-процессов, а не как графический редактор. Он разделяет работу на четыре независимых уровня: бизнес-логика, BPMN-семантика, геометрия и экспорт. Такой подход нужен, потому что визуально красивая схема может быть логически неверной, а формально корректный BPMN XML может оставаться нечитаемым из-за плохих стрелок.

## 2. Главные возможности

### Интервью и наводящие вопросы

Перед моделированием Hermes определяет, какой информации не хватает. Навык содержит набор вопросов для выяснения:
- цели процесса;
- стартового события;
- результата;
- участников;
- внутренних и внешних ролей;
- последовательности действий;
- решений `Да/Нет`;
- повторных циклов;
- обязательных согласований;
- документов и данных;
- тестирования/приемки;
- параллельных действий;
- форматов и стиля выдачи.

Навык не должен задавать пользователю анкету из десятков вопросов сразу. Он задает короткие группы вопросов, причем только по неизвестным местам.

### BPMN-моделирование

Поддерживаются:
- Pool;
- Lane;
- Start Event;
- End Event;
- User Task;
- Service Task;
- Manual Task;
- Exclusive Gateway (XOR);
- Parallel Gateway (AND);
- Sub-Process;
- Sequence Flow;
- Message Flow;
- Data Object;
- Text Annotation.

### Корректная организационная семантика

Критически важное правило:
- если участники — подразделения одной организации, они оформляются как Lanes одного Pool;
- если участник независим от процесса/организации, он может быть отдельным Pool;
- Sequence Flow не пересекает Pool;
- Message Flow не используется между Lanes одного Pool.

### Работа с существующими схемами

Навык можно применять не только для создания с нуля, но и для:
- исправления BPMN;
- преобразования обычной блок-схемы;
- преобразования swimlane-диаграммы;
- разбора скриншота;
- внесения точечных изменений без изменения остальной модели.

### Контроль стрелок

Навык рассматривает стрелки как часть спецификации, а не декор:
- наконечник заканчивается на границе элемента;
- вход в Task/Gateway перпендикулярен;
- нет диагоналей;
- нет прохода через чужие BPMN-блоки;
- нет слияния разных возвратов;
- нет стрелок поверх Lane border;
- разные входы в один Task получают разные точки подключения;
- `Да/Нет` располагаются рядом с нужной веткой.

### Полный экспорт

При наличии зависимостей создаются:

| Формат | Назначение |
|---|---|
| `.bpmn` | основной редактируемый BPMN 2.0 |
| `.xml` | BPMN XML |
| `.svg` | векторная схема |
| `.pdf` | печать/презентация |
| `.png` | высокое разрешение |
| `.jpg` | легкий просмотр |
| `.webp` | компактный web-формат |
| `.tiff` | полиграфический/архивный raster |
| `.eps` | векторный обмен через Inkscape |
| `.html` | локальный просмотр |
| `.json` | исходная семантическая модель |
| `.md` | краткое описание |
| `.txt` | отчет проверки |
| `.zip` | полный пакет |

## 3. Почему используется промежуточная JSON-модель

Hermes не должен сразу рисовать XML из свободного текста. Сначала он создает `process-model.json`. Это дает три преимущества:

1. Бизнес-логика отделена от графики.
2. Можно изменить одну стрелку или один этап без перегенерации смысла всей схемы.
3. Легко валидировать роли, связи, решения и маршруты.

Схема JSON находится в `templates/process-model.schema.json`.

## 4. Как навык принимает решение: Pool или Lane

### Пример 1 — внутренний заказчик

Если отдел продаж, маркетинг, аналитики и разработка принадлежат одной компании:
- один Pool компании;
- четыре Lanes;
- между ними Sequence Flow.

### Пример 2 — внешний клиент

Если клиент — независимая организация:
- Pool компании;
- отдельный Pool клиента;
- коммуникация между ними Message Flow.

## 5. Как навык моделирует согласования

Для каждого согласования фиксируется:
- объект согласования;
- владелец решения;
- критерии;
- ветка `Да`;
- ветка `Нет`;
- исполнитель доработки;
- обязательные повторные проверки.

Например:

`Подготовить договор → Согласовать договор → Договор согласован?`

- `Да → Подписать договор`
- `Нет → Доработать договор → повторно согласовать`

Если после доработки обязательна юридическая проверка, навык не имеет права ее пропустить.

## 6. Как навык моделирует тестирование

Навык не объединяет разные тестирования только потому, что они называются «проверкой».

Например:
- внутреннее функциональное тестирование — выполняет команда;
- приемочное — бизнес-заказчик;
- пользовательское — конечные пользователи.

У каждого вида может быть свой Gateway и свой маршрут `Нет`.

## 7. Как формируется краткое описание

После генерации создается `brief-description.md`.

Структура:
1. что показывает схема;
2. где начинается процесс;
3. какие главные этапы проходит;
4. где находятся ключевые согласования/контроли;
5. что происходит при замечаниях;
6. чем заканчивается процесс.

Краткое описание рассчитано на устный доклад руководителю и обычно занимает 3–6 предложений.

## 8. Контроль качества

Навык не ограничивается проверкой XML.

### Структурная проверка
- sourceRef/targetRef существуют;
- ID уникальны;
- корректная принадлежность к Lane;
- корректные типы flow;
- Start/End Event не нарушают базовые правила;
- Gateway имеют выходы;
- меж-pool связи не оформлены Sequence Flow.

### Геометрическая проверка
- endpoints на границах;
- ортогональные сегменты;
- вход перпендикулярен;
- стрелки не проходят через чужие nodes;
- нет Task на границе Lane;
- нет коллинеарного наложения Flow.

### Визуальная проверка
После автоматического PASS Hermes обязан просмотреть SVG/PDF и проверить:
- не перекрыт ли текст;
- не выглядят ли линии слитыми;
- видны ли наконечники;
- читаются ли ветки `Да/Нет`;
- не перепутана ли принадлежность к Lane.

## 10. Установка в Hermes

Hermes использует навыки как каталоги с обязательным `SKILL.md`. Пользовательский навык можно положить, например, в:

```bash
~/.hermes/skills/process-modeling/bpmn-diagramming
```

Проверка окружения:

```bash
python ~/.hermes/skills/process-modeling/bpmn-diagramming/scripts/check_env.py
```

Тестовый запуск:

```bash
python ~/.hermes/skills/process-modeling/bpmn-diagramming/scripts/build_bpmn.py \
  ~/.hermes/skills/process-modeling/bpmn-diagramming/examples/simple-approval.json \
  --out ./bpmn-test
```

Hermes также поддерживает установку навыков из URL/каталога в зависимости от используемой версии CLI.

## 11. Зависимости

Python:
- lxml
- Pillow
- PyMuPDF

Системная зависимость:
- Inkscape — только для EPS.

Навык содержит `check_env.py`, который показывает, чего не хватает.

## 12. Ограничения

- Автоматическая маршрутизация подходит для большинства линейных процессов, но сложные BPMN с большим числом возвратов могут потребовать ручных `waypoints`.
- Наличие корректного BPMN XML не гарантирует визуальную читаемость — поэтому визуальный review обязателен.
- Скрипт не заявляет официальную OMG XSD validation без реально подключенной официальной XSD.
