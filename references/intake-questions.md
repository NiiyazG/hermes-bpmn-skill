# Наводящие вопросы

Задавай **только отсутствующие** вопросы. Сначала максимум 3–6 критичных.

## 1. Границы процесса
1. Как называется процесс?
2. Какова его бизнес-цель?
3. Что запускает процесс?
4. Что считается успешным завершением?
5. Какой итоговый результат/артефакт должен быть получен?

## 2. Участники
1. Кто выполняет действия?
2. Какие роли/подразделения относятся к одной организации?
3. Есть ли внешний клиент, поставщик, регулятор или подрядчик?
4. Кто владеет процессом?
5. Кто принимает ключевые решения?

## 3. Основной маршрут
1. Назовите последовательность действий без ошибок и возвратов.
2. Какие шаги обязательны?
3. Какие шаги можно пропускать по условию?
4. Есть ли параллельные действия?

## 4. Решения и возвраты
Для каждого решения:
- какой вопрос задается;
- кто отвечает;
- что означает `Да`;
- что означает `Нет`;
- кто выполняет доработку;
- какая проверка повторяется после доработки.

## 5. Согласования
- Что согласуется?
- Кем?
- По каким критериям?
- Нужно ли повторное согласование после любых изменений?

## 6. Тестирование/приемка
- Есть внутреннее функциональное тестирование?
- Есть приемка бизнес-заказчиком?
- Есть пользовательское тестирование?
- Кто выполняет каждый вид?
- Куда идет процесс при отрицательном результате?

## 7. Данные и документы
- Какие документы поступают на вход?
- Какие документы создаются?
- Какие данные/справочники нужны?
- Какие отчеты/выходные формы формируются?

## 8. Вывод
- Язык диаграммы?
- Нужен фирменный стиль?
- Нужны ли логотип/цвета?
- Один широкий лист или дополнительно A3/A4?
- Нужен ли краткий доклад?

## Политика вопросов
Если пользователь дал изображение, сначала извлеки ответы из изображения. Не спрашивай то, что можно прочитать. Если пользователь просит «без вопросов» — зафиксируй разумные предположения и пометь их в brief/validation report.
